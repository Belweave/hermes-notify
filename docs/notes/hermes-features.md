# Hermes companion implementation and public contracts

Source pin: [`ed1afb082eb3e46cf2edae9d8f68fb67b09ee4df`](https://github.com/NousResearch/hermes-agent/tree/ed1afb082eb3e46cf2edae9d8f68fb67b09ee4df), inspected from `.local/hermes-source` on November 4, 2026. These are contracts at that commit, not a claimed minimum released Hermes version. No installed user profile, credential file or settings file was read. No Notify send, deployment, native app build or browser preview was performed.

## Recommendation to the parent

Ship the connected workflow: an explicit release tool produces a persistent workspace, fast approval observers correlate the original request with that run, the native transport answers only that host request, and the optional Desktop pane reads the same secret-free snapshot. Return replies as attributed input to their originating task. These interactions are useful together without a second chat client, a transcript scrape, a custom execution tool or an inbound gateway adapter.

Keep subagent status, HTML widgets and custom media views as future additions with specific use cases. They are real public features, but the current workspace has neither media outputs nor the session identity a reliable transcript card needs. A read-only run card would otherwise be liable to resolve against the currently selected profile instead of the chat that owns it.

Three integration details need the parent's attention:

1. **Register the packaged skill explicitly.** The native entrypoint should call `from .skills import register as register_skills` and `register_skills(ctx)`. The helper is implemented in `skills/__init__.py`; the entrypoint is outside this task's ownership. The reliable explicit skill name is `hermes-notify:notify-release-workspace`. Native packages do not acquire skills just by having a `skills/` directory. Public method: [`plugins_content.py:32-68`](https://github.com/NousResearch/hermes-agent/blob/ed1afb082eb3e46cf2edae9d8f68fb67b09ee4df/hermes_cli/plugins_content.py#L32-L68); usage: [`plugins/index.md:1175-1202`](https://github.com/NousResearch/hermes-agent/blob/ed1afb082eb3e46cf2edae9d8f68fb67b09ee4df/website/docs/developer-guide/plugins/index.md#L1175-L1202).
2. **Use the documented session-context helper in the runtime.** The staged catalog check passed but warned about `hermes_notify/tools.py` importing `hermes_cli.plugin_session.session_key`. `gateway.session_context.get_session_env("HERMES_SESSION_KEY", "")` is the public, catalog-allowed equivalent. Keep the explicit `session_id` supplied to tool handlers too. See [`plugins/index.md:1816-1822`](https://github.com/NousResearch/hermes-agent/blob/ed1afb082eb3e46cf2edae9d8f68fb67b09ee4df/website/docs/developer-guide/plugins/index.md#L1816-L1822) and [`plugin_validate_private_imports.py:62-66`](https://github.com/NousResearch/hermes-agent/blob/ed1afb082eb3e46cf2edae9d8f68fb67b09ee4df/hermes_cli/plugin_validate_private_imports.py#L62-L66). The warning is in a runtime-owned file; this task did not edit it.
3. **The snapshot has no App launch URL.** The pane displays App registrations and validated artifact links, and directs the user to the App's Notify notification. It does not derive an unverified URL from `appId`, inspect publisher settings, or call Notify. If direct App launching from Desktop is wanted, agree on a bounded safe launch-URL field with the runtime and amend `docs/IMPLEMENTATION.md` first. The current contract remains unchanged.

## Implemented surface

- `desktop/plugin.js`: plain ESM, opt-in pane plus full page/sidebar contribution. Apps, runs, pending decisions and delivery health; validated HTTPS artifact links use `ctx.os.openExternal`. No approval controls, mutation calls, raw bridge access, session reads, file APIs or direct fetches.
- Queries use the shared SDK React Query client. An eight-second status-read deadline, zero inactive cache retention, route/epoch checks and disposal cancellation prevent stale profile data from publishing. Mounted active work refreshes every 15 seconds while visible. Idle/unconfigured/error states do not run interval polling; explicit refresh and focus can retry. No background worker or persistent UI state is installed.
- `dashboard/plugin_api.py`: one synchronous `GET /api/plugins/hermes-notify/status`, run by FastAPI off the event loop. Uses the public non-writing `PluginState.data_dir` property on each request. Opens only `status.json`, rejects symlinks/nonregular files, reads at most 512 KiB plus one byte, validates and projects documented fields, and returns `Cache-Control: no-store`. Unknown fields are discarded; errors do not return paths, file contents or exception details. No writes or arbitrary file/URL parameters.
- Reader bounds are 20 runs, 50 decisions, 50 delivery rows, 20 checks/artifacts per run, and the workspace string limits. The runtime writes up to 10 runs and 30 decisions/deliveries with a 480 KiB output bound, below the reader's 512 KiB cap. The producer remains responsible for keeping allowed text fields secret-free; schema validation cannot recognize a credential embedded in ordinary summary text.
- `dashboard/manifest.json`, `index.js`, `style.css`: declared backend plus a hidden explanatory component for the separate Web Dashboard loader. This is not a second dashboard implementation or a native mobile surface.
- `desktop/assets/`: unmodified official [Paper Mono](https://paper.design/mono) variable WOFF2, SIL Open Font License and archive/font SHA-256 provenance. `desktop/scripts/embed-font.py` reproducibly embeds the font into plugin-owned styles because disk ESM is evaluated as a blob and cannot resolve a relative font import. No runtime font download. Weight range is 100 through 800, with monospace fallback. Scoped selectors and documented `--ui-*`/`--color-*` variables leave the host DOM and theme intact.
- `skills/notify-release-workspace/SKILL.md` and `skills/__init__.py`: explicit release workflow and native registration helper. Covers the actual tool schemas, begin/update/finish, template publication versus URL registration, measured stages, original-session replies, exact native approval transport, and real release-command success plus verification before shipped. The skill grants no permission.

## Verification and exact limits

Development dependencies are pinned in `desktop/tests/requirements.txt`. Create `desktop/tests/.venv` with `python3 -m venv desktop/tests/.venv` and install that requirements file there. The following commands passed from the repository root using isolated fixture homes and no real Notify request:

```sh
node --check desktop/plugin.js
node --experimental-vm-modules --test desktop/tests/plugin.test.mjs
desktop/tests/.venv/bin/python -m pytest -q dashboard/tests
desktop/tests/.venv/bin/python desktop/tests/catalog_check.py
desktop/tests/.venv/bin/python ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/notify-release-workspace
```

Results: **9 JavaScript tests and 26 backend tests passed**, and the skill validator passed. The JavaScript suite checks exports against the pinned real SDK, executes that source's actual import scanner, runs ESM registration with a small SDK/React harness, and tests route-switch/abort/unload races, polling bounds, missing setup, safe link clicks and font integrity. The backend suite imports the real public `PluginState`, exercises FastAPI routes, proves context-local profile selection reaches a sync handler, and covers no-directory-creation, read-only methods, projection, size/shape limits, malformed JSON, symlinks, directory/FIFO rejection and safe errors.

The real pinned `validate_plugin_dir` ran on a frozen temporary copy of the current combined package. Receipt: `desktop/tests/catalog-result.json`. All admission checks passed, including Desktop surface, capability registration, security scan and core-override checks. One runtime-owned private-import warning is detailed above. Isolation correctly reports `in_process` because the package registers an approval transport. The lightweight environment lacks `requests`, so the validator also printed optional builtin import warnings for delegation, terminal and X search; the collision scan is not equivalent to booting a complete Hermes installation. No release compatibility floor is declared or established by this check.

The Python test environment used Python 3.15 with FastAPI/httpx and emitted Starlette's httpx deprecation warning. Node 26.12.1 emitted expected experimental VM/type-strip warnings. The tests are behavioral and static checks, **not a live renderer or host authentication test**. No Desktop/Webapp UI was opened, no visual screenshot was taken, and no installed profile was loaded. Authentication and runtime enablement gates are verified by source contract, not by launching the full server. No real phone delivery/display, sign-in, approval round trip or publication is claimed. Parent integration must register the skill and rerun the combined-package checks after runtime changes.
